### Задание 1

1. Перейдите в каталог [**src**](https://github.com/netology-code/ter-homeworks/tree/main/01/src). Скачайте все необходимые зависимости, использованные в проекте.

3. Выполните код проекта. Найдите  в state-файле секретное содержимое созданного ресурса **random_password**, пришлите в качестве ответа конкретный ключ и его значение.
4. Раскомментируйте блок кода, примерно расположенный на строчках 29–42 файла **main.tf**.
Выполните команду ```terraform validate```. Объясните, в чём заключаются намеренно допущенные ошибки. Исправьте их.
5. Выполните код. В качестве ответа приложите: исправленный фрагмент кода и вывод команды ```docker ps```.
6. Замените имя docker-контейнера в блоке кода на ```hello_world```. Не перепутайте имя контейнера и имя образа. Мы всё ещё продолжаем использовать name = "nginx:latest". Выполните команду ```terraform apply -auto-approve```.
Объясните своими словами, в чём может быть опасность применения ключа  ```-auto-approve```. Догадайтесь или нагуглите зачем может пригодиться данный ключ? В качестве ответа дополнительно приложите вывод команды ```docker ps```.
8. Уничтожьте созданные ресурсы с помощью **terraform**. Убедитесь, что все ресурсы удалены. Приложите содержимое файла **terraform.tfstate**. 
9. Объясните, почему при этом не был удалён docker-образ **nginx:latest**. Ответ **ОБЯЗАТЕЛЬНО НАЙДИТЕ В ПРЕДОСТАВЛЕННОМ КОДЕ**, а затем **ОБЯЗАТЕЛЬНО ПОДКРЕПИТЕ** строчкой из документации [**terraform провайдера docker**](https://library.tf/providers/kreuzwerker/docker/latest).  (ищите в классификаторе resource docker_image )

### Решение

1. Результат команды ```terraform init ```:

![screen](screenshots/3.png)

2. Согласно файлу **.gitignore** личную, секретную информацию следует хранить в файле **personal.auto.tfvars**

3. Результат команды ```terraform apply ```:

![screen](screenshots/4.png)

Находим в файле **terraform.tfstate** секретное содержимое созданного ресурса **random_password** ```6QjSvqJk684tOVNd```

![screen](screenshots/5.png)

4. После раскомментирования блок кода пытаемся выполнить ```terraform validate```, получаем ошибку. Terraform указывает на допущенные ошибки:
 - ресурсы должны иметь два лейбла (тип ресурса и название), в коде же указан только тип ресурса "docker_image"
 - имя должно начинаться с буквы или символа подчеркивания, в коде имя "1nginx"

![screen](screenshots/6.png)

Исправляем указанные ошибки, так же исправляем строку ```name  = "example_${random_password.random_string_FAKE.resulT}"``` на ```name  = "example_${random_password.random_string.result}"```

5. В итоге исправленый код будет выглядеть так:

```
resource "docker_image" "nginx" {
  name         = "nginx:latest"
  keep_locally = true
}

resource "docker_container" "nginx" {
  image = docker_image.nginx.image_id
  name  = "example_${random_password.random_string.result}"

  ports {
    internal = 80
    external = 9090
  }
}

```

Выполняем команду ```terraform validate```:

![screen](screenshots/7.png)

Выполняем команду ```terraform apply```:

![screen](screenshots/8.png)

Выполняем команду ```docker ps```:

![screen](screenshots/9.png)


6. Меняем имя контейнера на ```hello_world```, выполняем команду ```-auto-approve```, terraform создает ресурсы без подтверждения, опасность состоит в невозможности еще раз проверить все создаваемые, изменяемые и удаляемые ресурсы перед начало работы terrafform. Возможно данный ключ может пригодиться, когда нет возможности ввести ```yes```, например в скриптах.

![screen](screenshots/9.png)

![screen](screenshots/10.png)

### Задание 2*

1. Создайте в облаке ВМ. Сделайте это через web-консоль, чтобы не слить по незнанию токен от облака в github(это тема следующей лекции). Сгенерируйте разные пароли через random_password и передайте их в контейнер, используя интерполяцию из примера с nginx.(```name  = "example_${random_password.random_string.result}"```  , двойные кавычки и фигурные скобки обязательны!)

```
      - "MYSQL_ROOT_PASSWORD=${...}"

      - MYSQL_ROOT_HOST="%"
```
